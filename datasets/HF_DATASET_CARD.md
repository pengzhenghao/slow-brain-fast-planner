# Slow Brain, Fast Planner

Dataset accompanying [Slow Brain, Fast Planner](https://github.com/pengzhenghao/slow-brain-fast-planner) and the paper *"Slow Brain, Fast Planner: Latency-Resilient VLM-Augmented Urban Navigation"*.

This repository hosts two splits as top-level subfolders. It remains private pending redistribution authorization and privacy review, independently of code or paper publication. Authentication alone does not grant access; an explicit access grant is required. Pick whichever matches your use case. The paper additionally evaluates on a routine-scenario pool recorded by a partner delivery-robot fleet; that data cannot be redistributed and is not part of this release.

| Subfolder | Size | Episodes | Stored clips | Evaluated in paper | Purpose |
|---|---:|---:|---:|---:|---|
| `mini/`   | ~125 MB | 1 | 3 | 3 | CI / quickstart smoke test |
| `hard/`   | ~10.9 GB | 32 | 1,414 | 1,412 | Primary paper evaluation; semantically challenging scenarios |

The benchmark excludes two hard records at runtime because their GT future is mostly backward (`bad_gt_future:gt_mostly_backward`), producing the paper’s 1,412-scenario evaluation set.

## Quickstart

```bash
git clone https://github.com/pengzhenghao/slow-brain-fast-planner
cd slow-brain-fast-planner
uv sync && source .venv/bin/activate
hf auth login   # use an account explicitly granted access to the private dataset

# Mini split (~125 MB) for smoke tests:
python scripts/download_dataset.py --split mini      # writes data/slow-brain-fast-planner/mini/
python -m slow_brain_fast_planner.cli.trajectory_selection \
    --dataset data/slow-brain-fast-planner/mini --model dummy_argmax --write-report

# Hard split (~10.9 GB) for full paper evaluation:
python scripts/download_dataset.py --split hard      # writes data/slow-brain-fast-planner/hard/
```

`--split all` fetches everything; `--split <name>` uses HuggingFace `allow_patterns` so only the requested subfolder is downloaded.

## What's in each split

### `mini/` (1 episode + 3 takeover clips)

A single episode (`s2e_v2_20260115_224153`) with three takeover clips, intended for fast CI / quickstart sanity checks. Same canonical schema as the larger splits.

### `hard/` (32 episodes, 1,414 stored clips; 1,412 evaluated)

Primary evaluation split. Real-world sidewalk navigation snapshots flagged by human annotators for semantic challenges: intersections / Y-junctions, pedestrians or cyclists, terrain boundaries (grass / curb), obstacles, or ambiguous path choices. The paper reports VLM trajectory selection achieving ~30% ADE reduction over the planner baseline on this split.

- 32 driving episodes captured by a four-wheeled delivery robot on urban sidewalks.
- Sensors: forward RGB (mp4 + per-frame PNG samples), wheel odometry (5 Hz pose in map ENU frame), S2E planner candidates (64 anchor-based trajectories with scores per tick).
- Each takeover clip annotation: `label_takeover_request ∈ {0, 1}` indicates whether the human intervened at the clip center time.

## Layout (canonical episode schema v0.1.0)

Each split shares the same on-disk layout:

```
<split>/
├── dataset_manifest.json
├── episodes/
│   └── s2e_v2_<timestamp>/
│       ├── episode.json
│       ├── rgb.jsonl                  # video-backed RGB stream (5 Hz)
│       ├── odom.jsonl                 # robot pose in map ENU frame
│       ├── planner_candidates.jsonl   # S2E candidate trajectories + scores per tick
│       └── assets/rgb/
│           ├── front.mp4              # canonical RGB video (fisheye)
│           ├── front_pinhole.mp4      # pinhole-projected RGB (for planner input)
│           └── sample_*.png           # individual frames referenced by takeover_clips
└── takeover_clips/
    ├── takeover_clips.jsonl
    └── summary.json
```

See the [code repo](https://github.com/pengzhenghao/slow-brain-fast-planner) for the schema definition (`src/slow_brain_fast_planner/schema/canonical_episode.py`) and the takeover-clip construction logic (`src/slow_brain_fast_planner/benchmarks/takeover_clips.py`).

## Local planner

Trajectory candidates were generated by an ONNX local planner. The planner itself is optional: every split ships `planner_candidates.jsonl`, so all shipped evaluations run with `--planner-source prelogged` and do not need the ONNX model. The planner weights are not distributed here.
